# golang-core v0.8.26 patch (409 conflict, json errors for any accept)

Changes on top of v0.8.25 needed by the api for the history of an ai chat: a write of the history names the
version it was read at, and a write made against an older version is refused with `409 Conflict` and the current
version (a second tab of the same chat stops its own answer). The branch `conflict-409-and-json-errors` holds them; the
api uses it through a `replace` until a release is cut.

## 1. `http.ErrConflict`

`http/error.go`: a new error next to the other status errors. Wrapped with `%w` (alone or joined with a coded
error of the caller), it is rendered with `409`.

## 2. 409 in the response renderer

`http/response_renderer.go`:

- `ResponseRendererImpl.Error` maps `ErrConflict` to `fasthttp.StatusConflict`, between `ErrPaymentRequired` and
  `ErrRequestEntityTooLarge`. The body is what `ProtocolRenderer.Error(409, err)` returns, the same way as for
  every other status, so the api renders its usual `ErrorResponse`;
- `ResponseRenderer` gains `Conflict(ctx, err)` and `ResponseRendererImpl` implements it like `PaymentRequired`
  (`Error` with `errors.Join(ErrConflict, err)`).

`http/response.go`: the package level helper `Conflict(ctx, errs...)`, like `PaymentRequired`.

The interface change breaks an implementation of `ResponseRenderer` outside this module; the api has none (it
builds `NewResponseRenderer` with its own `ProtocolRenderer`).

## 3. An error is rendered whatever the `Accept` of the client

`http/response.go`, `http/response_renderer.go`: `ResponseRendererImpl.Error` rendered its body through
`renderResponse`, which fails on an `Accept` that names no format the renderer knows. A streaming client of the
api ai proxy sends `Accept: text/event-stream`: a refusal of the proxy (402, 400, 401, 403) came back as
`200 OK` with an empty body, and only the log said `getting output format: can't recognize data format`.

- `renderResponse` is split: the format is resolved first, the body is written by `renderResponseAs(ctx, status,
  message, format)`;
- `Error` renders through `renderErrorResponse`, which falls back to json when the `Accept` names no known
  format. A known format of the `Accept` (json, protobuf, x-protobuf, `*/*`) is still used as before;
- `Ok` and `Created` are unchanged: an unknown `Accept` still leaves their body empty.

## Tests

- `http/render_test.go`: the 409 mapping in `TestResponseRendererErrorMapping`, `Conflict` in
  `TestResponseRendererErrorHelpers` and in the package level helpers, a wrapped `ErrConflict` keeps its message in
  the body (`TestResponseRendererConflictWrapped`).
- `http/render_test.go`: an error under `Accept: text/event-stream`, `application/xml` and a json range with
  `q=0` keeps its status with a json body (`TestResponseRendererErrorUnsupportedAccept`); a known format next to
  an unknown one is used (`TestResponseRendererErrorKnownAccept`).

`go build ./...` and `go test ./...` are green. `make lint` does not start with the local golangci-lint
(`exhaustruct_v5` is unknown to it); with that one line removed from a copy of the config the repository has 6
issues, all of them on `main` already (`http_client/do_stream_test.go`, `preloader/preloader_test.go`), none in
the changed files.
